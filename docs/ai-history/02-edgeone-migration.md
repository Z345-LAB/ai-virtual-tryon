# 02 · 云函数化改造：把 Express 塞进 EdgeOne Pages

> 时间：2026-10-21 凌晨
> 对应提交：`e80fe1f` `8e3e587` `c988ec0` `786581e`

## 人的意图（原话）

> 但是我不是买了个腾讯的域名吗，直接部署在腾讯的免费服务器上。

这句背后有两个隐含信息，AI 先澄清再动手：**域名不等于服务器**，而且这个项目有持密钥的后端，不能纯静态托管。

## 第一步：澄清技术前提

AI 没有直接开干，而是先讲清一件事：

> 域名只是门牌号，真正要选的是"房子"。这个项目不是纯静态：`index.html` 可以托管，但它还有一个持有百炼密钥的 Node 后端（密钥绝不能放进前端）。所以「纯静态托管」这条路，点按钮一定 404。

然后给出三个候选方案对比（轻量服务器 / 云开发 / EdgeOne Pages），并用一次选择问出来：

- 部署方式 → **EdgeOne Pages**
- 备案状态 → **我选的好像是不用备案的那一种**（即「全球（不含中国大陆）」加速区域）

## 第二步：先查文档，再写代码

AI 没有凭印象写云函数，而是查了 EdgeOne Pages 官方文档，拿到三条决定性事实：

| 事实 | 为什么关键 |
|---|---|
| 云函数目录是 `cloud-functions/`，文件路径即路由 | 决定目录结构 |
| 单次执行默认 **30 秒**，可在 `edgeone.json` 配到 10–120 秒 | 直接判死刑：原来的异步轮询最长 150 秒 |
| Node 运行时 v20，请求/响应体上限 6MB | 决定只能回传 URL，不能回传图片 |

## 第三步：一个参数推翻旧架构

原实现是「异步建任务 + 每 3 秒轮询」，最长 150 秒 —— 与 30 秒上限冲突。

AI 没有去缩短轮询，而是**改问一个更根本的问题**：能不能一次同步拿到图？

```bash
POST /api/v1/services/aigc/multimodal-generation/generation   # 不带 X-DashScope-Async 头
→ HTTP 200 | 耗时 10s | 直接返回 image_url
```

结果：**同步调用 10 秒**，比原来的异步轮询（16 秒）还快，且只发一个请求。

> 这是本阶段最重要的一次判断：**遇到平台限制，先质疑自己的架构，而不是去适配限制**。

## 第四步：把状态从内存里赶出去

3D 的任务状态原来存在服务端 `Map` 里。但边缘节点是分布式的，存了也读不到。

改造：`task_id = t3d_<base36 时间戳>`，状态由时间推导，任何节点都能算出同一结果。**无状态化是能上云函数的前提**。

## 第五步：前端与源码分离

`index.html` 从仓库根目录移到 `public/`，EdgeOne 的输出目录设为 `public`。

原因：如果输出目录是根目录，`server.js`、`package.json` 都会变成可公开访问的静态资源。

## 阶段产出

| 文件 | 作用 |
|---|---|
| `cloud-functions/_lib/{wan,http,three}.js` | 前后端共用核心逻辑 |
| `cloud-functions/api/{health,tryon,create3d,check3d}.js` | 四个云函数入口，文件即路由 |
| `server.js` | 本地 Express 入口，与线上共用同一份 `_lib` |
| `edgeone.json` | `maxDuration: 60` |
| `public/index.html` | 前端，接口路径统一为 `/api/*` |

**设计要点**：本地和线上跑的是**同一份核心代码**，只是入口不同。这样本地调通的行为可以直接相信线上。
