# 06 · 三候选：从「AI 替我选风格」到「同描述的三种可能」

> 时间：2026-10-23
> 对应提交：`3a4f456` `09802b5` `3bb25ae` `a2597c4`
> 主题：**AI 理解偏了怎么办** —— 这条链的价值不在做成了什么，而在两次被纠正的过程

---

## 第一轮：我提需求，AI 做偏了

**我的原话**：

> 一次造三套造型并排对比，可以在 2D 三视图那一步实现，选定一版 2D 三视图再去生成 3D。

**AI 的实现**：写死了三个预设提示词，各生成一张。

```js
const TRIPLE_PRESETS = [
  { tag: '古风', prompt: '穿着飘逸的古风汉服，发髻与流苏点缀，织金暗纹' },
  { tag: '赛博', prompt: '穿着赛博朋克机能外套，霓虹光带与金属扣件' },
  { tag: '礼服', prompt: '穿着深色丝绒长礼服，金属肩饰与垂坠裙摆' },
];
```

界面标签也跟着变成「古风 / 赛博 / 礼服」，卡片按钮写「选这套 →」。

从代码看没 bug，跑起来也确实是三张并排。**但方向错了。**

---

## 我纠正它

**我的原话**：

> 2D 生成三个图让用户自己选那一个功能，是用户输入一段描述，他自动生成同一描述下的不同样式
> 有点类似于抽卡……都是基于用户描述的风格的，**不是自己跳出三种不同的风格自己选**。

**AI 的修改建议**（这次它先复述问题，再动手）：

> 我把它做成了三种不同风格，等于替用户改了风格。改法是：用用户的原话并行跑三次，
> 差异来自模型自身的采样随机性，而不是由程序注入不同提示词。

```js
// 改动前：三种风格
prompt: PRESET[i].prompt

// 改动后：同一段描述，三次采样
VARIANT_LABELS.map(() => fetch('/api/tryon', { prompt: 用户输入的原文 }))
```

标签从「古风/赛博/礼服」改成「方案 1/2/3」，因为它们本来就是同一风格。

**这一轮的关键判断**：多候选的"差异"必须来自模型采样，不能来自程序改提示词。
一旦程序替用户改风格，功能就从"帮用户表达"变成了"替用户决定"。

---

## 第二轮：我自己发现漏锁

**我的原话**：

> 开始换装未禁用又出现了，把这个补上。连续点击会开出第二批任务，等于双倍扣费。

**AI 排查后的发现**（比"加个 disabled"更重要）：

> 上锁写在几个 `await` 之后——取预设图、读底图数据都要等，这段窗口内按钮仍然可点，
> 快速双击能开出第二批任务（一次 6 张，两倍花费）。

**修改建议**：

```js
// 改动前
const personData = await getPersonDataUrl();   // ← 这里还没锁
state.busy = true;

// 改动后：锁在函数第一行，所有 await 都在锁内
state.busy = true;
syncControls();
try { ... } finally { state.busy = false; syncControls(); }
```

同时引入 `pending` 状态（结果已出、尚未选定）：这期间锁住所有能重新开一批的入口，
按钮文案改成「请先选定一张」，只留「选一张」和「返回」两条路。

---

## 第三轮：我指出"下一步不明确"

**我的原话**：

> 三张候选出来之后，没有明确的下一步指向「生成 3D」，用户不知道点哪里。

**AI 的方案**：不是改文案，而是在选定后让舞台底部浮出一个墨色主按钮
「生成 360° 3D 展示 →」，直接复用 3D 逻辑。

**理由**：用户的视线在三张卡上，指引应该出现在视线附近，而不是让他回左栏找。

---

## 沉淀下来的三条规则

| 规则 | 触发它的具体情况 |
| --- | --- |
| 多候选的差异只能来自模型采样，不能来自程序改提示词 | 第一轮做成了"三种风格" |
| 锁必须同步加在函数入口，不能放在 `await` 之后 | 第二轮双击能开出两批任务 |
| 引导按钮要出现在用户视线所在处，而不是"逻辑正确的位置" | 第三轮出完图不知道点哪 |

## 一句话总结

这条链里 AI 没有一次是"不会写"，三次都是**理解偏了**：
把"三种可能"做成"三种风格"、把"禁用"做成"晚一拍禁用"、把"指引"做成"只改文案"。
每次都是我用一句具体的描述把它拉回来——**说清"我要什么"比说清"怎么写"更有效**。
