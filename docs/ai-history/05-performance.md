# 05 · 性能攻坚：从「模型太大」到「组件根本没起来」

> 时间：2026-10-21 中午
> 对应提交：`123c51d` `89cf641` `0c796e9` `5d5df6f` `9d3b537`
> 这一段包含**两次认知修正**，是"猜测 → 测量 → 推翻 → 再测量"的完整案例。

## 第一次修正：慢，不等于模型大

> 用户：2D 出来了，但 3D 产出太慢。这是它本来就慢，还是哪里有问题？另外这是一键体验的主路径，演示时如果等太久，体验就断了。

AI 先拆成两件事回答：

1. **真实图生 3D 本来就慢**：行业常态 30–90 秒，不是代码问题
2. **但这次的慢不在 Tripo**：当时余额为 0、运行时无 fetch，走的是演示路径，慢在从美国 CDN 下载 2.8MB 的宇航员模型

实测：

```
model-viewer JS (jsdelivr)     935KB / 2.6s
Astronaut.glb (modelviewer.dev) 2.87MB / 11.4s
RobotExpressive.glb            464KB
```

于是换成 464KB 的本地托管模型（提交 `89cf641`），并把演示任务的假进度从 6 秒压到 2 秒——正好命中前端第一次轮询，点击后约 3 秒出模型。

## 一次被误解的改动

> 用户：等一下，我记得一键体验预设的是一张二次元少女立绘，为什么现在出来的是别的图？

AI 立刻核对代码并如实说明：**预设图 `PRESET_IMG_URL` 一个字没改**，改的是"3D 兜底占位模型"。并承认这是产品设计上的误导：

> 那个机器人不是你图生成的，它是"占位"。所以你感觉"少女图进去、机器人出来"——这个困惑是我埋的坑。

这里体现的协同原则：**用户质疑时先自证（贴代码行号），再承认设计问题，不要辩解**。

## 第二次修正：10 分钟不是"再等等"

> 用户：已经超过十分钟了，一直是模型载入中。

AI 停止等待，开始测量。把 42MB 的 glb 下载下来解剖：

```
1 mesh / 1,390,236 三角面 / 722,267 顶点
贴图 3 张合计 4.17MB   ← 其余 ~38MB 全是网格数据
extensionsUsed: 无 Draco / meshopt（不需要外部解码器）
CORS: Access-Control-Allow-Origin: *（不是跨域问题）
CDN 速度: 1.74MB/s（不是网络问题）
```

并用同一套 model-viewer 在本地渲染这个文件 → **黑屏**（同样环境下 464KB 的模型正常）。

结论：**v3.1 默认输出的是"雕刻级"高模，网页端扛不住**。

### 用参数解决体积

AI 直接调用 v3 接口验证 `face_limit` 是否有效（花一次积分，值得）：

| | 默认 | `face_limit=30000` |
|---|---|---|
| 体积 | 42.1 MB | **4.98 MB** |
| 三角面 | 1,390,236 | **29,782** |
| 耗时 | 86 s | 80 s |

`face_limit` **不在加价项里**，30 credits 不变。对比之下 P1 游戏级模型要 60–80 credits——所以推荐先用免费的 `face_limit`。

> 用户问过：游戏低级模型是不是花的积分少？
> AI 如实回答：**反而更贵**，因为重拓扑是额外加工，不是简单减面。

## 第三次修正：5MB 也卡，说明问题不在体积

> 用户：显示「3D 模型过大，浏览器加载超时 · 已切换为演示模型」。

这句话是 AI 自己写的兜底文案，反过来成了线索：**5MB 的模型也 60 秒没触发 `load`**。

于是重新审视线索链：

```
model-viewer 组件从 cdn.jsdelivr.net 加载（935KB）
→ 手机网络下失败是静默的：没有报错，没有提示，界面只是转圈
→ <model-viewer> 自定义元素没注册，设置 src 完全无效，load 永远不会触发
```

修复三件套（提交 `9d3b537`）：

1. 组件搬到本地 `public/vendor/`，不再依赖境外 CDN
2. 加载时**不再用 `display:none` 藏它**（部分浏览器下不触发 load），改用提示层覆盖
3. 加 `ensureModelViewerReady`：8 秒内元素没注册就明确报错，不再假死

本地用同一份本地组件 + 模型实测，渲染正常。

## 本阶段的方法论

| 现象 | 第一反应（错） | 实测后（对） |
|---|---|---|
| 3D 慢 | 模型太大 | 美国 CDN 下载 2.8MB |
| 42MB 加载不出来 | 网络慢，再等等 | 139 万面，浏览器渲染不动 |
| 5MB 也加载不出来 | 模型还是太大 | **组件根本没加载，load 事件不存在** |

**核心教训：每一条"看起来合理"的解释，都要用一个可测量的量去证伪。**
